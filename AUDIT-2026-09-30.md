# Audit — 2026-09-30: the tokens package, and where the two apps disagree

**Scope:** this package, plus the **cross-repo** findings: the places where `babel-admin-panel` and `babel-mobile` render the same idea differently. Contracts, status tones, formatters and feedback timing belong here because this package is where a shared answer would live. Companion records: `babel-mobile/docs/COMPONENT_AUDIT_2026-09-30.md`, `babel-admin-panel/docs/component-audit-2026-09-30.md`, `base_mobile_library/AUDIT-2026-09-30.md` and `base_nodejs_library/AUDIT-2026-09-30.md`.

**Method.** The audit covered sixteen dimensions across the five repos, and an independent verifier re-measured every finding and tried to refute it. Of the 385 findings kept, 17 are about this package and 69 are cross-repo.

## Verdict

- **The package builds and passes its own gate**: drift, 28/28 WCAG pairs, contracts and version parity. Adoption is uneven. Space, radius and motion are widely used; type, shadow and contracts reach almost no consumer code. Mobile uses BabelSpace 3,014 times, while both apps keep their own type ladders.
- **The contracts have zero consumers.** Admin imports nothing from `contracts`, and mobile never imports `babel_contracts.dart`. Both apps type task status, priority, trade, condition, limits and error codes by hand. Two contracts are also too stale to adopt as they stand: NOTIFICATION_TYPE is missing 58 of the API's 182 types, and ERROR_CODES is missing 27 codes admin branches on and 45 mobile branches on.
- **The two apps disagree on what the user sees.** Across 10 status vocabularies (64 value pairs), 20 pairs render a different tone on admin and mobile. Only two vocabularies agree fully, and both are held together by comments. There is no status-to-tone contract. Beyond colour, the same stored preference renders dates differently ("Sep 4, 2026" against "09/04/2026"), and so do currency ("CA$" against "$"), the French region default (fr-CA against fr-FR), error-toast lifetime (persistent against 4 s), and confirm semantics (admin has a destructive variant; mobile had none until this branch).
- **Gaps both apps fill by hand:**
  - disabled treatment: 6 opacities on admin, 3 on mobile;
  - focus ring width;
  - minimum touch target: 44 on some mobile sites, 48 on others;
  - icon sizes: 35 distinct values on mobile;
  - alpha and scrim values;
  - skeleton colours: mobile's are 1.13–1.32:1 against white;
  - a pressed-state role.

## What changed on this branch

- `tokens.flat.json` now carries every group. The build walks the groups instead of a hand-kept list, so `border` is no longer dropped (`0e96d2f`).
- Shadow tokens are emitted to Dart as `BabelShadowLight` / `BabelShadowDark`. This is additive; neither app renders the package shadows yet (`a5d1da3`).
- `npm run verify` analyses both generated Dart files, and the skip message names what went unchecked (`a2406d6`).
- Version 0.8.0. The CHANGELOG is backfilled from 0.3.0, and verify now fails a release that has no entry (`5566c79`).
- Stale pins, broken snippets and consumer facts are fixed in README, dart/README and DESIGN.md (`4ca2a27`, `af0af98`). DESIGN.md §7 no longer suggests re-exporting this Babel-branded package from the brand-neutral base_mobile_library.

In the apps: admin moved from v0.6.0 to v0.7.0 and spends `--border-accent-rail` (admin `4036dd8`). Mobile's confirm dialog gained the destructive variant admin already had (mobile `9d0d4309`). Admin's violation badges no longer render grey (admin `0683642`).
